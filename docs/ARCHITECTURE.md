# 아키텍처

재생 파이프라인의 구조와, 구현할 때 지켜야 할 규칙을 적습니다. 2026-11-13에 구현한 내용에 맞춰 고쳤습니다. 구현이 달라지면 이 문서를 함께 고칩니다.

## 한눈에 보기

```
                    ┌──────────────┐
   파일 ──────────▶ │ 디먹스 스레드 │
                    └──────┬───────┘
              영상 패킷 큐 │ 소리 패킷 큐
            ┌──────────────┴──────────────┐
            ▼                             ▼
   ┌─────────────────┐          ┌──────────────────┐
   │ 영상 디코드 스레드│          │ 소리 디코드 스레드 │
   │ D3D11VA / SW    │          │ 디코딩 → atempo  │
   └────────┬────────┘          └────────┬─────────┘
      프레임 큐 (GPU 텍스처)          링 버퍼 (PCM)
            ▼                             ▼
   ┌─────────────────┐          ┌──────────────────┐
   │ 렌더 스레드      │ ◀─시계── │ 소리 출력 콜백    │
   │ 색 변환 → 화면   │          │ WASAPI           │
   └─────────────────┘          └──────────────────┘

   UI 스레드: 창 메시지 → 명령(재생, 탐색, 배속…) → 각 스레드
```

데이터는 위에서 아래로만 흐릅니다. 명령은 UI 스레드에서 각 스레드로 채널을 통해 내려갑니다.

## 스레드

| 스레드 | 하는 일 | 막히는 곳 |
|---|---|---|
| UI (메인) | Win32 메시지 루프, 입력을 명령으로 변환 | 없음. 어떤 것도 기다리지 않음 |
| 디먹스 | 파일을 읽어 패킷을 종류별 큐에 넣음 | 패킷 큐가 가득 찼을 때 |
| 영상 디코드 | 패킷을 프레임으로 | 프레임 큐가 가득 찼을 때 |
| 소리 디코드 | 패킷을 PCM으로, 배속 필터 적용 | 링 버퍼가 가득 찼을 때 |
| 렌더 | 시계에 맞는 프레임을 골라 화면에 표시, 컨트롤 그리기 | 재생 중에는 스왑체인 대기 객체(수직 동기), 일시정지·끝·빈 화면에서는 깨우기 신호 |
| 소리 콜백 | 링 버퍼에서 꺼내 장치에 전달 | OS가 소유. 절대 막히면 안 됨 |

D3D11 디바이스는 렌더 스레드가 시작할 때 만들고(`Event::Gpu`로 UI에 알림), 세션을 닫을 때는 스레드를 별도의 "reaper" 스레드에서 거둬 UI가 기다리지 않게 합니다. 영상·소리 디코드 스레드는 디먹스 스레드가 파일을 연 뒤 띄우고 끝날 때 거둡니다.

규칙은 네 가지입니다.

- **UI 스레드는 FFmpeg와 Direct3D를 직접 부르지 않습니다.** 창을 끌거나 크기를 바꾸는 동안 Win32 메시지 루프가 멈추는데, 렌더 스레드가 따로 있으므로 재생은 끊기지 않습니다. 탐색할 때도 UI 스레드는 큐의 세대만 올리고(`GenQueue::advance`), 낡은 패킷과 프레임의 해제는 꺼내는 스레드가 합니다.
- **스레드 사이의 통신은 채널과 큐뿐입니다.** 비동기 런타임은 쓰지 않습니다. 다른 스레드가 UI 스레드에 알릴 때는 `mpsc` 채널에 사건을 넣고 `PostMessage`로 깨웁니다.
- **소리 콜백 안에서는 잠금, 할당, 파일 접근을 하지 않습니다.** 링 버퍼(`ring.rs`)와 소리 시계 관측값(`ObservationCell`, 시퀀스 잠금)은 원자 변수만 씁니다.
- **렌더 스레드는 매 프레임 그리기 전에 스왑체인 대기 객체를 기다립니다.** 기다리지 않으면 `Present`가 수직 동기까지 막히고, 그동안 디바이스 잠금 때문에 디코더도 화면 갱신 속도에 묶입니다 ([DECISIONS](DECISIONS.md)의 D20).

## 큐와 역압

모든 큐는 크기가 정해져 있습니다. 큐가 차면 앞 단계가 멈추고, 그 힘이 파일 읽기까지 거슬러 올라갑니다. 일시정지하면 큐가 차서 모든 스레드가 잠들고 CPU 사용이 0이 됩니다.

| 큐 | 크기 | 비고 |
|---|---|---|
| 영상 패킷 큐 | 비트레이트 기준 약 2초 분량, 2~12MB | 바이트 기준. 비트레이트를 모르면 12MB |
| 소리 패킷 큐 | 1MB | 바이트 기준 |
| 영상 프레임 큐 | 4장 | 4K 한 장이 약 12MB(P010은 24MB)이므로 작게 유지 |
| 소리 링 버퍼 | 용량 약 400ms, 채우는 양 120ms | 단일 생산자, 단일 소비자. 적게 채워 배속 변경이 늦게 들리지 않게 함 |

M5에서 실측해 조정했습니다. 처음의 패킷 큐 16MB 고정은 로컬 파일에서 늘 가득 차 메모리만 차지해(1080p60 재생 중 개인 메모리 136MB) 비트레이트 기준으로 줄였습니다(125MB). 비어 있는 큐에는 용량보다 큰 패킷 하나도 들어갈 수 있게 해, 아주 큰 패킷에 파이프라인이 멈추지 않게 합니다.

큐의 모든 항목에는 **세대 번호**가 붙습니다. 탐색할 때마다 세대를 올리고, 각 스레드는 낡은 세대의 항목을 버립니다. 이것으로 탐색 직후 옛 프레임이 섞여 나오는 문제를 막습니다. 세대를 올릴 때 낡은 항목의 비용은 바로 빼므로, 새 세대의 항목은 낡은 항목이 남아 있어도 용량을 다 쓸 수 있습니다. 영상 디코더는 새 세대의 첫 프레임을 넣기 전에 프레임 큐의 낡은 항목을 직접 해제해(`purge_stale`) 디코더 텍스처 풀이 마르지 않게 합니다.

## 시계와 동기화

기준은 소리입니다. 사람은 소리의 끊김에는 민감하고 프레임 하나의 지연에는 둔감하기 때문입니다.

- **소리 시계**: 지금 스피커에서 나오고 있는 샘플의 미디어 시각입니다. 콜백이 링 버퍼에서 꺼낸 위치의 미디어 시각과, cpal 타임스탬프로 잰 장치 지연을 더한 "언제 스피커에 닿는가"를 관측값으로 남깁니다.
- **벽시계**: 재생 시계(`clock.rs`)의 바탕입니다. 경과 시간에 배속을 곱합니다. 소리가 나오는 동안 렌더 스레드가 매 갱신마다 소리 관측값으로 보정합니다. 150ms 넘게 어긋나면 바로 맞추고, 그 아래는 10%씩 줄이며, 4ms 아래는 무시합니다. 관측값이 0.25초 넘게 오지 않으면(소리 없음, 장치 없음, 소리 끝) 벽시계만으로 갑니다. 그래서 소리가 없거나 장치가 사라져도 같은 시계로 재생이 이어집니다.
- **배속**: 시계의 배속은 새 배속의 소리가 스피커에 닿을 때 바꿉니다 (D21). 소리가 없으면 바로 바꿉니다.
- **영상**: 렌더 스레드가 화면 갱신마다 시계를 읽고, 다음 갱신 때의 시각(한 갱신 주기를 더한 값)에 맞는 프레임을 큐에서 고릅니다. 그보다 앞선 프레임은 건너뜁니다. 디코더도 시계보다 50ms 넘게 늦은 프레임은 화면에 올리기 전에 버려, 디코딩이 재생을 못 따라갈 때 따라잡습니다.

배속 필터를 거치면 소리의 길이가 바뀌므로, 링 버퍼에 넣는 덩어리마다 원래의 미디어 시각과 그때의 배속을 함께 기록해 둡니다. 출력 덩어리의 미디어 시각은 필터에 넣은 첫 프레임의 시각부터 "출력 샘플 수 ÷ 샘플레이트 × 배속"만큼 늘려 셉니다.

## 영상 경로

### 디바이스 공유

D3D11 디바이스를 하나만 만들어 디코더와 렌더러가 함께 씁니다. 이것이 "프레임은 GPU를 떠나지 않는다"의 전제입니다.

1. `D3D11_CREATE_DEVICE_VIDEO_SUPPORT`와 `D3D11_CREATE_DEVICE_BGRA_SUPPORT`로 디바이스를 만듭니다. 뒤의 것은 Direct2D 때문에 필요합니다.
2. `av_hwdevice_ctx_alloc`으로 FFmpeg 하드웨어 컨텍스트를 만들고, `AVD3D11VADeviceContext.device`에 이 디바이스를 넣은 뒤 `av_hwdevice_ctx_init`을 부릅니다.
3. 코덱 컨텍스트에 `hw_device_ctx`를 주고, `get_format`에서 `AV_PIX_FMT_D3D11`을 고릅니다.
4. 프레임 큐에 잡아 두는 장수만큼 `extra_hw_frames`를 늘립니다. 디코더의 텍스처 풀은 크기가 고정이라, 이 값이 모자라면 디코딩이 멈춥니다.

디코딩된 프레임은 `data[0]`에 `ID3D11Texture2D`, `data[1]`에 텍스처 배열의 인덱스를 담고 있습니다. 포맷은 8bit면 NV12, 10bit면 P010입니다.

> **주의.** FFmpeg와 렌더 스레드가 같은 디바이스 컨텍스트를 쓰므로 `AVD3D11VADeviceContext`의 `lock` / `unlock`으로 양쪽을 직렬화해야 합니다. 구현에서는 FFmpeg가 만든 기본 잠금을 `Gpu::lock()`으로 감싸 렌더 스레드(VideoProcessor와 Direct2D)와 소프트웨어 프레임 업로드가 잡습니다. 디바이스에는 `ID3D11Multithread::SetMultithreadProtected`도 켭니다. `Present`는 이 잠금 밖에서 부릅니다.

`extra_hw_frames`는 프레임 큐 장수 + 4입니다. 기준 PC에서 줄여도 시스템 메모리는 줄지 않았습니다 (텍스처는 GPU 메모리).

### 색 변환과 출력

NV12/P010을 화면용 RGB로 바꾸는 일은 D3D11 VideoProcessor에 맡깁니다. 색 변환, 크기 조절, 회전을 한 번의 `VideoProcessorBlt`로 스왑체인 백버퍼에 바로 씁니다.

- 스왑체인은 플립 모델(`DXGI_SWAP_EFFECT_FLIP_DISCARD`), BGRA 8bit, 버퍼 3장, 최대 프레임 지연 2, 대기 객체 사용입니다 (D20).
- 입력과 출력의 색공간(BT.601, BT.709, BT.2020, PQ, HLG)을 프레임 정보대로 지정합니다 (`media/color.rs`가 FFmpeg 값으로 분류, 지정되지 않으면 높이 720 미만은 BT.601). HDR은 VideoProcessor가 SDR로 바꾸며, 드라이버의 지원 보고는 믿지 않고 `VideoProcessorBlt`가 실패할 때만 SDR BT.2020으로 낮춥니다 (D22).
- 화면 비율과 회전 메타데이터는 출력 사각형(`ui/layout.rs`의 `fit_video`)과 회전 설정으로 처리합니다.

> **M1에서 확인함 (2026-11-13, RTX 2060).** 디코더가 만든 텍스처를 VideoProcessor 입력으로 그대로 쓸 수 있습니다. 드라이버가 입력 뷰 만들기를 거부하면 해당 슬라이스를 별도 텍스처로 GPU 안에서 복사한 뒤 입력으로 쓰는 우회로를 넣어 두었습니다 (`gfx/present.rs`). 이 경우에도 시스템 메모리는 거치지 않습니다.

### 컨트롤 그리기

같은 백버퍼 위에 Direct2D로 컨트롤 바와 OSD를 그린 뒤 `Present`합니다. 글자는 DirectWrite, 아이콘은 도형으로 직접 그려서 이미지 파일을 싣지 않습니다.

일시정지 중에는 렌더 루프를 멈추고, 화면이 바뀌어야 할 때만 다시 그립니다.

### 소프트웨어 폴백

하드웨어 디코딩을 쓸 수 없으면 CPU로 디코딩한 프레임을 NV12/P010 텍스처에 올리고, 이후는 같은 경로를 탑니다. 렌더러는 프레임이 어디서 왔는지 모릅니다.

- 변환은 `swscale` 없이 직접 합니다 (D19). 8bit는 NV12, 그보다 깊으면 P010입니다.
- 텍스처는 `D3D11_BIND_DECODER`로 만들어야 VideoProcessor 입력 뷰가 만들어집니다 (기준 PC에서 `SHADER_RESOURCE`만으로는 `E_INVALIDARG`). 텍스처는 디코더가 풀로 재사용하고, `UpdateSubresource`로 올릴 때 GPU 잠금을 잡습니다.

폴백으로 넘어가는 경우는 다음과 같습니다.

- GPU가 그 코덱이나 프로파일을 지원하지 않을 때 (예: HEVC 4:2:2). FFmpeg의 `get_format`이 하드웨어 형식 없이 다시 불려 그대로 소프트웨어로 디코딩합니다.
- AV1: FFmpeg 자체 `av1` 디코더는 하드웨어 전용이라 디코딩 중에 넘어갈 수 없습니다. 열기 전에 GPU의 AV1 디코더 프로파일을 확인하고, 없으면 처음부터 `libdav1d`로 엽니다.
- 디코딩 중 하드웨어 오류가 연달아 3번 났을 때. 소프트웨어 디코더로 다시 열고, 새 디코더가 키프레임부터 읽도록 지금 위치로 다시 탐색합니다.
- 디바이스를 잃었을 때 (드라이버 재시작 등). 렌더 스레드가 새 디바이스를 만들고, UI가 같은 파일을 같은 위치와 재생 상태로 다시 엽니다.

## 소리 경로

```
디코딩 → atempo (배속) → 포맷 변환 (장치의 샘플레이트, 채널, f32) → 링 버퍼 → 콜백 (음량 적용)
```

- 배속은 libavfilter의 `atempo`로 음정을 유지한 채 바꿉니다. 필터 그래프에는 `atempo`를 늘 두 단계 두고, 2배 이하면 (배속, 1), 넘으면 (2, 배속/2)로 나눕니다.
- 배속을 바꿀 때는 필터 그래프를 다시 만들지 않고 두 단계에 `tempo` 명령을 보냅니다 (`avfilter_graph_send_command`).
- 다운믹스와 장치 형식 변환은 같은 그래프의 `aresample`, `aformat`이 합니다. 출력은 장치의 기본 형식(공유 모드의 샘플레이트와 채널 수, f32)입니다.
- 음량은 콜백에서 샘플에 곱합니다 (음량의 제곱). 시스템 음량은 건드리지 않습니다.
- 출력 장치가 사라져 cpal이 오류를 알리면 1초마다 새 기본 장치로 다시 열어 봅니다. 그동안은 소리 패킷을 디코딩하지 않고 버리며 벽시계로 영상만 재생합니다. 소리 디코더를 열 수 없으면 소리를 끄고 디먹스가 소리 패킷을 넣지 않게 합니다.
- 기본 장치를 바꿔도 이전 장치가 살아 있으면 그쪽으로 계속 나옵니다. 장치 변경 알림(`IMMNotificationClient`)은 받지 않습니다 (알려진 한계).

## 탐색

1. UI 스레드가 목표 시각과 함께 세대를 올리고, 세 큐의 세대를 올리고, 시계를 목표에 세워 둡니다 (`SessionShared::seek`). 렌더 스레드가 기다릴 탐색으로 기록합니다.
2. 디먹스 스레드가 탐색 요청을 가져가 목표 앞의 키프레임으로 파일 위치를 옮기고(`avformat_seek_file`의 최대값을 목표로), 새 세대로 패킷을 넣습니다.
3. 디코더는 새 세대의 패킷을 보면 내부 버퍼를 비웁니다. 소리 스레드는 링 버퍼도 비웁니다(`discard`).
4. 모드에 따라 첫 프레임을 정합니다.
   - **빠른 탐색**: 키프레임을 바로 보여 줍니다. 탐색 바를 끄는 동안 씁니다.
   - **정확한 탐색**: 목표 시각 전의 프레임은 디코딩만 하고 버립니다. 소리도 목표 앞은 버립니다. 키 입력과 탐색 바를 놓았을 때 씁니다. 목표가 파일 끝을 넘으면 마지막으로 버린 프레임을 보여 줍니다.
5. 렌더 스레드가 새 세대의 첫 프레임을 보여 주며 시계를 그 프레임에 맞추고, 재생 중이면 시계를 다시 흐르게 한 뒤 UI에 알립니다 (`Event::SeekSettled`). 그때까지 화면에는 이전 프레임이 남아 있습니다.

탐색 요청이 처리 중에 또 들어오면 중간 것은 버리고 마지막 목표만 처리합니다. `→`를 누르고 있어도 밀리지 않게 하기 위해서입니다. 상대 이동(`←`, `→`)은 화면의 위치가 아니라 처리 중인 목표에서 셈하므로, 연달아 눌러도 누른 만큼 이동합니다. 파일을 여는 것도 "0초로의 빠른 탐색"처럼 다뤄, 첫 프레임이 나올 때까지 시계를 세워 둡니다.

## 상태

```
비어 있음 ──열기──▶ 여는 중 ──▶ 재생 ◀──▶ 일시정지
    ▲                 │          │           │
    └────오류─────────┘          └──▶ 끝 ◀───┘
```

탐색은 별도 상태가 아니라 재생이나 일시정지 위에 얹히는 일시적 동작입니다. 일시정지 중에 탐색하면 새 프레임 한 장만 보여 주고 다시 멈춥니다.

## 모듈 구조

crate는 하나입니다. 워크스페이스로 나누지 않습니다.

```
src/
  main.rs          진입점, 명령줄 인자
  player.rs        상태 기계와 명령 처리, 배속 단계, 시간·배속 표시 (순수)
  clock.rs         재생 시계와 소리 관측값 (순수)
  queue.rs         세대 번호가 붙은 유한 큐, 미리 읽기 크기 (순수)
  ring.rs          소리 링 버퍼, 미디어 시각 표시 (순수, 잠금 없음)
  shared.rs        스레드가 함께 쓰는 상태, 깨우기 신호, 사건, 진단 시간 측정
  render.rs        렌더 스레드: 프레임 선택, 시계 보정, 그리기, 디바이스 손실 처리
  audio_out.rs     출력 장치(cpal), 콜백, 음량
  media/
    mod.rs         세션: 파일 하나의 스레드와 큐, 탐색, 일시정지, 배속
    demux.rs       파일 열기, 패킷 읽기, 탐색
    video.rs       영상 디코딩 (D3D11VA, 소프트웨어 폴백, NV12/P010 변환)
    audio.rs       소리 디코딩, atempo 필터 그래프
    color.rs       색공간 판정 (순수)
    pack.rs        소프트웨어 프레임을 NV12/P010으로 옮기기 (순수)
    ffi.rs         FFmpeg 원시 API의 작은 소유 래퍼
  gfx/
    device.rs      D3D11 디바이스, FFmpeg 하드웨어 컨텍스트, 스왑체인
    present.rs     VideoProcessor 변환
    overlay.rs     Direct2D 컨트롤 바와 OSD
  ui/
    window.rs      Win32 창, 메시지 루프, 전체화면, DPI, 끌어다 놓기, 파일 열기 대화상자
    input.rs       키를 명령으로 (순수)
    layout.rs      컨트롤 바 배치, 클릭 위치 판정, 영상 사각형, 처음 창 크기 (순수)
```

**순수 로직과 플랫폼 코드를 섞지 않습니다.** `(순수)`로 표시한 모듈은 Windows API를 부르지 않게 만들어, 어느 OS에서나 `cargo test`로 검증합니다. 현재 Windows PC에서는 이 테스트와 함께 하드웨어 디코딩, 화면 출력, 소리 출력도 직접 검증합니다.

UI 스레드의 창 프로시저는 앱 상태를 `RefCell`로 빌립니다. `SetWindowPos`나 창 크기 조절의 모달 루프에서 다시 불리는 메시지(`WM_SIZE`, `WM_DPICHANGED` 등)는 앱 상태를 빌리지 않고 공유 상태만으로 처리합니다. 파일 열기 대화상자도 자기 메시지 루프를 돌리므로 앱 상태를 빌리지 않은 채로 띄웁니다.

## 패키지와 실행 환경

Rust로 만든 Win32 앱을 MSIX에 담습니다. Store 배포를 위해 UI 툴킷을 바꾸지 않습니다. 패키징 절차와 검증 기준은 [DISTRIBUTION](DISTRIBUTION.md)에 있습니다.

- 일반 사용자 권한으로 실행하고 설치 폴더에 파일을 쓰지 않습니다.
- 패키지의 설치 위치나 현재 작업 디렉터리를 고정 경로로 가정하지 않습니다.
- 명령줄, 파일 열기, 끌어다 놓기, 패키지 파일 연결의 입력은 같은 파일 열기 명령으로 모읍니다. 패키지 매니페스트의 파일 연결은 `Parameters="&quot;%1&quot;"`로 경로를 첫 인자로 넘깁니다. 설치한 패키지에서의 실제 전달은 아직 확인하지 못했습니다 (M0 스파이크 C).
- 필요한 FFmpeg DLL이 있다면 패키지 안에 함께 넣습니다. 시스템 전역 코덱 설치는 하지 않습니다.
- C 런타임은 실행 파일에 정적으로 넣어 VC++ 재배포 패키지에 기대지 않습니다 (D18). 실행 파일에는 아이콘, 버전 정보, 앱 매니페스트(모니터별 DPI v2, `asInvoker`, 긴 경로)를 리소스로 넣습니다 (`packaging/gongplayer.rc`).
- 설치, 업데이트, 제거는 Store와 Windows가 담당하며, 재생 파이프라인과 분리합니다.

## Concat에서 참고할 것

Concat(`concat-media`)에 비슷한 문제를 푼 코드가 있습니다. Concat은 AGPL이므로 코드를 복사하지 않고 접근 방식만 참고합니다.

| 파일 | 참고할 점 | 다른 점 |
|---|---|---|
| `hardware.rs` | 하드웨어 디코더 선택과 실패 시 폴백 처리 | Concat은 프레임을 시스템 메모리로 복사합니다. GongPlayer는 GPU에 둡니다 |
| `audio.rs` | `atempo` 단계 나누기, 프레임 사이에 남는 샘플 처리 | Concat은 내보내기용 필터 그래프입니다. GongPlayer는 재생 중에 배속을 바꿉니다 |
| `decode.rs` | 회전 메타데이터, 타임스탬프 처리 | Concat은 임의 위치 프레임 추출이 중심입니다. GongPlayer는 순차 재생입니다 |
