# 로드맵

MVP까지 일곱 단계입니다. 위험한 것을 먼저 확인하는 순서로 짰습니다. 기간은 기존 재생기 구현 기준의 어림값이며, MSIX 패키징 작업을 M0에서 확인한 뒤 재산정합니다. Store 계정 확인, 라이선스 검토, 심사 대기 시간은 아래 기간에 포함하지 않습니다.

각 단계는 "완료 기준"을 실제 Windows PC에서 확인해야 끝난 것입니다. 작업을 마치면 체크박스를 채웁니다.

| 단계 | 내용 | 기간 |
|---|---|---|
| M0 | 기반과 위험 확인 | 1~2일 |
| M1 | 영상 출력 | 3~4일 |
| M2 | 소리와 동기화 | 3~4일 |
| M3 | 일시정지, 탐색, 배속 | 3~4일 |
| M4 | 컨트롤과 조작 | 3일 |
| M5 | 견고성 | 4~5일 |
| M6 | 경량화와 배포 | 2~3일 |

## M0. 기반과 위험 확인

코드를 본격적으로 쓰기 전에, 계획을 뒤집을 수 있는 것부터 확인합니다.

- [x] `git init`, Cargo 프로젝트, 릴리스 프로필
- [ ] CI: Windows 러너에서 `fmt`, `clippy`, 빌드, 테스트 (워크플로 작성, 원격 실행은 아직 확인하지 못함)
- [x] 개발용 FFmpeg 고정: 사전 빌드 `win64-lgpl-shared`를 URL과 sha256으로 고정
- [x] 개발 흐름 결정: 현재 Windows PC에서 직접 개발하고 실행 (2026-11-13, D14)
- [x] Rust/MSVC, Windows SDK, FFmpeg 관련 개발 도구 설치 상태와 버전 확인 ([BUILD](BUILD.md))
- [x] 스파이크 A: 빈 Win32 창에 D3D11 스왑체인으로 단색 화면 표시
- [x] 스파이크 B: 최소 구성 FFmpeg 정적 라이브러리가 Rust 실행 파일에 링크되는지 확인 (MSVC + 정적, D24)
- [x] 스파이크 C: 최소 Win32 앱의 MSIX 생성, 개발용 설치·실행·제거, 파일 연결 활성화 확인 ([DISTRIBUTION](DISTRIBUTION.md)). 실제 플레이어(정적 빌드)로 확인
- [ ] 공개 배포를 위한 프로젝트 라이선스, FFmpeg 재링크 방법, 코덱 특허 검토 시작
- [ ] 테스트 영상 세트 수집 ([BUILD](BUILD.md)의 목록). 합성 영상 생성 스크립트 준비, 실제 영상은 `TestVideos/a.mp4` 하나 (1번 성격)
- [x] 기준 PC 사양을 [BUILD](BUILD.md)에 기록

**완료 기준**

- Windows PC에서 `cargo run`이 창을 띄웁니다.
- CI가 통과합니다.
- 스파이크 B의 결론이 [DECISIONS](DECISIONS.md)에 적혀 있습니다. 실패하면 앱 내부 구성을 "exe와 최소 DLL"로 바꾸고 같은 MSIX에 넣습니다.
- 스파이크 C에서 최소 앱이 패키지로 설치되고 실행·제거되며, 파일 연결로 전달한 경로를 받을 수 있습니다. 이 검증은 Store 심사 통과를 뜻하지 않습니다.

## M1. 영상 출력

가장 위험한 부분입니다. 디코더 텍스처가 복사 없이 화면까지 가는지 확인합니다.

- [x] 명령줄 인자로 받은 파일 열기, 영상 스트림 고르기
- [x] 디먹스 스레드와 패킷 큐
- [x] D3D11 디바이스를 FFmpeg와 공유, D3D11VA 디코딩
- [x] VideoProcessor로 NV12/P010을 백버퍼에 변환
- [x] 렌더 스레드: 벽시계 기준으로 프레임 표시
- [x] 창 크기 변경 시 비율 유지

**완료 기준**

- 1080p H.264와 4K HEVC 10bit 파일이 제 속도로 끝까지 재생됩니다.
- 작업 관리자에서 GPU의 Video Decode 사용이 보이고, CPU 사용은 한 자릿수 %입니다.
- 창을 끌거나 크기를 바꾸는 동안에도 재생이 끊기지 않습니다.

**확인 기록** (2026-11-13, 기준 PC, 합성 영상)

- 확인함: 1080p30 H.264, 4K30/4K60 HEVC 10bit가 하드웨어 디코딩(D3D11VA)으로 디코더 텍스처를 복사 없이 VideoProcessor에 넘겨 제 속도로 재생. 4K60 HEVC 10bit에서 CPU 0.12%(16 논리 코어 기준), 성능 카운터의 Video Decode 21.5%. 전체화면 전환 때 비율 유지.
- 확인 못 함: 창을 손으로 끌거나 크기를 바꾸는 동안의 끊김 여부 (구조상 렌더 스레드가 따로 돌아 끊기지 않아야 함).

## M2. 소리와 동기화

- [x] 소리 디코드 스레드, 장치 포맷으로 변환, 다운믹스
- [x] 출력 장치 열기, 링 버퍼, 콜백
- [x] 소리 시계 구현, 렌더 스레드의 기준을 벽시계에서 소리 시계로 교체
- [x] 소리 없는 파일은 벽시계로 재생
- [x] `clock`, `queue` 단위 테스트

**완료 기준**

- 립싱크 테스트 영상에서 10분 재생 뒤 영상과 소리의 어긋남이 ±40ms 이내입니다.
- 소리 없는 영상과 5.1 채널 영상이 정상 재생됩니다.

**확인 기록** (2026-11-13, 기준 PC, 합성 영상)

- 확인함: 소리 시계 관측값과 재생 시계의 차이가 정상 재생 중 4ms 이내 (90초 재생, 2초마다 측정). 소리 없는 720p60과 5.1채널 AC-3 MKV가 제 속도로 재생되고 오류 없음.
- 확인 못 함: 립싱크 테스트 영상으로 실제 화면과 스피커 사이의 어긋남을 재는 것 (장치 지연을 cpal 타임스탬프로 보정하지만, 눈과 귀 또는 측정 장비가 필요). 10분 장시간 재생. 5.1 다운믹스를 귀로 확인하는 것.

## M3. 일시정지, 탐색, 배속

- [x] 상태 기계 (`player.rs`)
- [x] 일시정지: 시계 정지, 소리 출력 정지, 렌더 루프 휴면
- [x] 세대 번호를 이용한 탐색, 빠른 탐색과 정확한 탐색
- [x] 연속 탐색 병합
- [x] `atempo` 배속, 재생 중 변경
- [x] 파일 끝 처리
- [x] 키보드로 임시 조작 (아직 컨트롤 바 없음)

**완료 기준**

- `→`를 누르고 있어도 화면이 밀리지 않고 따라옵니다.
- 빠른 탐색에서 키 입력 뒤 100ms 안에 새 프레임이 나옵니다.
- 0.5~4배 모든 단계에서 음정이 유지되고 동기가 맞습니다.
- 일시정지 중 CPU 사용이 0%입니다.

**확인 기록** (2026-11-13, 기준 PC, 합성 영상, 창 메시지로 키 입력)

- 확인함: `→`를 60ms 간격으로 세 번 보내면 가운데 목표는 건너뛰고 마지막 목표만 처리 (병합). 탐색 요청부터 새 프레임 표시까지 31~53ms (정확한 탐색 기준이라 빠른 탐색은 더 짧음). 1.5, 3, 4, 0.5배에서 2초당 미디어 진행이 배속과 일치하고 화면이 시계를 0.03초 안으로 따라감 (D20 수정 뒤). 배속 변경 순간의 소리 시계 오차 9~41ms (D21). 일시정지 중 CPU 0.00%, 비디오 디코드 0% (10초 평균). 파일 끝의 마지막 프레임에서 멈추고 다시 재생하면 처음부터.
- 확인 못 함: 음정 유지는 귀로 듣지 않음 (atempo 사용). 키를 실제로 누르고 있는 상태 (자동 반복은 같은 메시지 연속이라 병합 경로는 같음).

## M5. 견고성

실제 파일과 실제 환경에서 깨지는 곳을 메웁니다.

- [x] 소프트웨어 디코딩 폴백, 재생 중 전환 포함
- [x] 회전 메타데이터, 화소 비율
- [x] 가변 프레임레이트
- [x] HDR(PQ, HLG) 영상을 SDR로 변환 (VideoProcessor에 맡김, D22. PQ 톤 매핑 없음)
- [x] 손상되거나 중간에 잘린 파일
- [x] 소리 장치 변경과 분리
- [x] 디바이스 손실, 모니터 변경, 절전 복귀
- [x] 재생 중 화면 꺼짐 방지
- [x] 큐 크기 실측과 조정

**완료 기준**

- 테스트 영상 세트 전부가 재생됩니다.
- 재생 중에 헤드폰을 뽑거나 창을 다른 모니터로 옮겨도 재생이 이어집니다.
- 아이폰 HDR 영상의 색이 바래 보이지 않습니다.

**확인 기록** (2026-11-13, 기준 PC, 합성 영상)

- 확인함: HEVC 10bit 4:2:2(GPU 미지원)와 AV1(RTX 2060은 AV1 하드웨어 없음, libdav1d)이 소프트웨어로 제 속도 재생. 디버그용 `GONG_FORCE_SW`로 H.264 소프트웨어 경로. 90도 회전 메타데이터 영상이 세로 창으로 열리고 바르게 표시. 가변 프레임레이트 영상. 합성 HLG/PQ 영상이 바래지 않음 (D22). moov가 앞에 있는 MP4를 절반에서 자른 파일은 남은 데까지 재생 후 멈춤, MKV 가운데 200KB를 망가뜨린 파일은 손상 구간을 건너뛰어 끝까지 재생, moov가 없는 MP4는 한 줄 오류. 큐 크기: 패킷 큐가 16MB 고정이면 늘 가득 차 있어 비트레이트 기준 약 2초 분량(2~12MB)으로 줄임 (1080p60 재생 메모리 136→125MB).
- 구현했지만 확인 못 함: 재생 중 하드웨어 → 소프트웨어 전환 (하드웨어 오류를 일으킬 방법이 없음), 소리 장치를 뽑거나 바꾸는 경우 (오류 콜백 뒤 1초마다 기본 장치를 다시 열고, 실패하면 영상만 재생), 디바이스 손실 (같은 위치에서 다시 열기), 모니터 변경, 절전 복귀, 화면 꺼짐 방지 (`SetThreadExecutionState`를 부르지만 `powercfg /requests`는 관리자 권한이 필요해 확인 못 함). 실제 테스트 영상 세트와 아이폰 HDR 영상.
- 알려진 한계: 기본 출력 장치를 바꿔도 이전 장치가 살아 있으면 그쪽으로 계속 나옵니다 (장치 변경 알림을 받지 않음).

| CI 러너에 GPU가 없음 | 자동 테스트가 소프트웨어 경로만 확인 | 순수 로직을 분리해 단위 테스트. 하드웨어 경로는 단계마다 수동 확인 |
| 디코더 텍스처를 VideoProcessor가 거부 | 복사 없는 경로가 일부 드라이버에서 실패 | M1에서 가장 먼저 확인. GPU 안에서 복사하는 우회로 준비 |
| 정적 링크의 툴체인·재링크 조건 | 단일 exe 목표가 흔들림 | M0 스파이크 B와 라이선스 검토. 필요하면 exe와 최소 DLL을 MSIX에 포함 |
| 패키징과 파일 활성화 | 직접 실행은 되지만 설치한 앱이 파일을 열지 못함 | M0 스파이크 C로 조기에 확인 |
| Store 제출 조건과 라이선스 | 구현을 마쳐도 공개 배포가 지연될 수 있음 | M0부터 검토하고, 구현 일정과 심사·배포 완료를 구분 |
| HDR 변환 품질이 드라이버마다 다름 | 일부 PC에서 색이 다르게 보임 | M5에서 GPU 제조사별 확인. 부족하면 셰이더로 직접 톤매핑 |
| GPU 제조사별 동작 차이 | 한 PC에서만 되는 코드 | 가능한 범위에서 Intel, NVIDIA, AMD 각각 확인 |
