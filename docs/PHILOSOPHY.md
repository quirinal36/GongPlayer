# 설계 철학

GongPlayer는 동영상을 재생합니다. 그 한 가지만 하고, 그 한 가지를 가장 빠르고 가볍게 합니다.

이 문서는 기능을 넣을지 뺄지, 어떤 방식으로 구현할지 망설여질 때 판단 기준으로 씁니다. 원칙끼리 부딪히면 번호가 앞선 원칙을 따릅니다.

## 원칙

### 1. PC에 깔린 코덱에 기대지 않는다

이 프로젝트가 시작된 이유입니다. 같은 파일이 어떤 PC에서는 재생되고 어떤 PC에서는 안 되는 일이 없어야 합니다.

디코더는 앱에 함께 넣습니다. 단일 실행 파일을 우선하되, 툴체인이나 라이선스 조건에 따라 필요한 DLL을 같은 패키지에 포함할 수 있습니다. 미디어 재생에 OS에서 빌리는 것은 창, GPU 드라이버, 소리 출력 장치뿐입니다.

### 2. 기능 추가의 기본값은 "넣지 않는다"

기능 하나는 코드, 버튼, 단축키, 버그, 크기를 함께 데려옵니다. 새 기능은 아래 세 질문에 모두 "예"일 때만 넣습니다.

- 영상을 볼 때마다 쓰는 기능인가?
- 없으면 영상을 제대로 볼 수 없는가?
- 아래 예산을 지키면서 넣을 수 있는가?

하나라도 "아니오"면 넣지 않고 [SPEC](SPEC.md)의 "나중 후보"에 적어 둡니다.

### 3. 가벼움은 숫자로 지킨다

"가볍다"는 느낌이 아니라 아래 예산 표입니다. 예산을 넘는 변경은 그대로 넣지 않습니다. 넘는 이유를 [DECISIONS](DECISIONS.md)에 적고 예산을 먼저 고칩니다.

### 4. 프레임은 GPU를 떠나지 않는다

디코딩, 색 변환, 크기 조절, 화면 출력을 모두 같은 GPU 디바이스 안에서 합니다. 프레임을 시스템 메모리로 복사하는 것은 하드웨어 디코딩이 안 될 때의 폴백 경로뿐입니다.

### 5. 입력에는 즉시 반응한다

키를 누르면 다음 화면 갱신에 반응이 보여야 합니다.

- 탐색은 가까운 키프레임을 먼저 보여 주고, 정확한 위치는 뒤따라 맞춥니다.
- UI 스레드는 디코딩이나 파일 읽기를 기다리지 않습니다.
- 연달아 들어온 탐색은 마지막 것만 처리합니다.

### 6. 멈추지 않는다

문제가 생겨도 볼 수 있는 만큼은 보여 줍니다.

- 하드웨어 디코딩이 실패하면 소리 없이 소프트웨어 디코딩으로 넘어갑니다.
- 손상된 구간은 건너뛰고 계속 재생합니다.
- 소리 장치가 사라져도 영상은 계속 나옵니다.
- 오류는 화면에 한 줄로 알립니다. 대화상자로 재생을 막지 않습니다.

### 7. 화면의 주인은 영상이다

컨트롤은 필요할 때만 나타났다가 사라집니다. 메뉴 막대, 사이드 패널, 팝업은 없습니다.

모든 기능은 키보드로 쓸 수 있어야 합니다. 화면의 버튼은 그중 눈으로 찾을 수 있어야 하는 최소한만 둡니다.

### 8. 설정이 없다

설정 화면도 설정 파일도 두지 않습니다. 선택지가 필요해 보이면 좋은 기본값 하나를 정합니다. 기본값을 못 정하겠다면 그 기능을 아직 충분히 이해하지 못한 것입니다.

### 9. 의존성은 빚이다

crate 하나마다 크기, 빌드 시간, 시작 시간, 유지 부담이 붙습니다. Windows API로 수십 줄이면 되는 일에 crate를 들이지 않습니다.

UI 툴킷, 비동기 런타임, 범용 렌더링 엔진은 쓰지 않습니다.

### 10. Windows 전용으로 만든다

크로스 플랫폼 추상화 계층을 두지 않고 Windows API를 직접 부릅니다. 이식성을 포기하는 대신 크기, 속도, 단순함을 얻습니다.

### 11. 측정한 것만 말한다

성능에 대한 주장에는 숫자와 측정 조건을 함께 적습니다. 측정하지 않은 것은 "목표"라고 부릅니다.

## 가벼움 예산

아래 숫자는 코드를 쓰기 전에 정한 목표입니다. M6에서 실측하고, 실측값에 맞춰 이 표를 고칩니다. 2026-11-13에 기준 PC([BUILD](BUILD.md))에서 합성 영상으로 잰 값을 넣었고, 맞출 수 없던 세 항목은 이유를 [DECISIONS](DECISIONS.md)의 D23에 적고 고쳤습니다 (2026-11-13 사용자 승인).

| 항목 | 목표 | 측정 조건 | 실측 (2026-11-13, 기준 PC) |
|---|---|---|---|
| 앱 실행 코드 | 단일 exe 우선, exe와 동봉 DLL 합계 10MB 이하 | 릴리스 빌드. DLL 사용 시에도 같은 합계 예산 적용 | 배포용(정적 최소 구성 FFmpeg + dav1d): 단일 exe 8.13MB, DLL 없음 (dav1d 전 6.35MB). 개발용은 exe 457KB + DLL 143MB |
| 설치 패키지 | MSIX. 압축 5MB 이하 (2026-11-13 실측으로 정함) | 실행 코드, 아이콘, 매니페스트, 고지문을 포함한 압축 크기와 설치 크기를 별도 기록 | 배포용: 압축 3.18MB, 설치 8.21MB (dav1d 포함) |
| 첫 프레임까지 | ~~200ms 이하~~ → **400ms 이하** (조정, D23) | 프로세스 시작부터 첫 프레임 표시까지, SSD의 1080p H.264 | 배포용 330~356ms (개발용 350~380ms), 부팅 뒤 첫 실행 915ms(개발용). 그중 `D3D11CreateDevice`만 230~250ms |

| 메모리 | ~~100MB 이하~~ → **재생에 더해지는 양 60MB 이하** (조정, D23) | 1080p 재생 중 개인 바이트에서 파일 없는 빈 창의 개인 바이트를 뺀 값 | 배포용: 빈 창 57MB, 1080p60 재생 110MB (+53MB). 개발용: 72MB, 125MB. 4K60 HEVC 10bit는 개발용 약 230MB |
| 프레임 누락 | 0 (주사율 차이로 생기는 누락은 제외, D23) | 1080p 60fps를 1배속으로 5분 재생 | 5분 동안 약 20초마다 1장씩 15장. 모두 60fps 영상을 59.94Hz 화면에 낼 때 생기는 것이고, 화면 갱신을 놓친 것은 0 |
