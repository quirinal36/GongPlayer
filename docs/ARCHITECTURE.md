# 아키텍처

재생 파이프라인의 구조와, 구현할 때 지켜야 할 규칙을 적습니다. 아직 코드가 없으므로 이 문서는 설계안입니다. 구현하면서 달라지는 부분은 이 문서를 고칩니다.

## 한눈에 보기

```
                    ┌──────────────┐
   파일 ──────────▶ │ 디먹스 스레드 │
                    └──────┬───────┘
              영상 패킷 큐 │ 소리 패킷 큐
            ┌──────────────┴──────────────┐
            ▼                             ▼
   ┌─────────────────┐          ┌──────────────────┐
   │ 영상 디코드 스레드│          │ 소리 디코드 스레드 │
   │ D3D11VA / SW    │          │ 디코딩 → atempo  │
   └────────┬────────┘          └────────┬─────────┘
      프레임 큐 (GPU 텍스처)          링 버퍼 (PCM)
            ▼                             ▼
   ┌─────────────────┐          ┌──────────────────┐
   │ 렌더 스레드      │ ◀─시계── │ 소리 출력 콜백    │
   │ 색 변환 → 화면   │          │ WASAPI           │
   └─────────────────┘          └──────────────────┘

   UI 스레드: 창 메시지 → 명령(재생, 탐색, 배속…) → 각 스레드
```

데이터는 위에서 아래로만 흐릅니다. 명령은 UI 스레드에서 각 스레드로 채널을 통해 내려갑니다.

## 스레드

| 스레드 | 하는 일 | 막히는 곳 |
|---|---|---|
| UI (메인) | Win32 메시지 루프, 입력을 명령으로 변환 | 없음. 어떤 것도 기다리지 않음 |
| 디먹스 | 파일을 읽어 패킷을 종류별 큐에 넣음 | 패킷 큐가 가득 찼을 때 |
| 영상 디코드 | 패킷을 프레임으로 | 프레임 큐가 가득 찼을 때 |
| 소리 디코드 | 패킷을 PCM으로, 배속 필터 적용 | 링 버퍼가 가득 찼을 때 |
| 렌더 | 시계에 맞는 프레임을 골라 화면에 표시, 컨트롤 그리기 | 수직 동기 |
| 소리 콜백 | 링 버퍼에서 꺼내 장치에 전달 | OS가 소유. 절대 막히면 안 됨 |

규칙은 세 가지입니다.

- **UI 스레드는 FFmpeg와 Direct3D를 직접 부르지 않습니다.** 창을 끌거나 크기를 바꾸는 동안 Win32 메시지 루프가 멈추는데, 렌더 스레드가 따로 있으므로 재생은 끊기지 않습니다.
- **스레드 사이의 통신은 채널과 큐뿐입니다.** 비동기 런타임은 쓰지 않습니다.
- **소리 콜백 안에서는 잠금, 할당, 파일 접근을 하지 않습니다.**

## 큐와 역압

모든 큐는 크기가 정해져 있습니다. 큐가 차면 앞 단계가 멈추고, 그 힘이 파일 읽기까지 거슬러 올라갑니다. 일시정지하면 큐가 차서 모든 스레드가 잠들고 CPU 사용이 0이 됩니다.

| 큐 | 초기 크기 | 비고 |
|---|---|---|
| 패킷 큐 (영상, 소리 각각) | 합계 16MB | 바이트 기준 |
| 영상 프레임 큐 | 4장 | 4K 한 장이 약 12MB이므로 작게 유지 |
| 소리 링 버퍼 | 약 200ms | 단일 생산자, 단일 소비자 |

크기는 출발값이고 M5에서 실측해 조정합니다.

큐의 모든 항목에는 **세대 번호**가 붙습니다. 탐색할 때마다 세대를 올리고, 각 스레드는 낡은 세대의 항목을 버립니다. 이것으로 탐색 직후 옛 프레임이 섞여 나오는 문제를 막습니다.

## 시계와 동기화

기준은 소리입니다. 사람은 소리의 끊김에는 민감하고 프레임 하나의 지연에는 둔감하기 때문입니다.

- **소리 시계**: 지금 스피커에서 나오고 있는 샘플의 미디어 시각입니다. 링 버퍼에서 꺼낸 위치의 시각에서 장치 지연을 뺀 값입니다.
- **벽시계**: 소리가 없는 파일이거나 소리 장치를 쓸 수 없을 때 대신 씁니다. 경과 시간에 배속을 곱합니다.
- **영상**: 렌더 스레드가 화면 갱신마다 시계를 읽고, 그 시각에 맞는 프레임을 큐에서 고릅니다. 이미 늦은 프레임은 버립니다.

배속 필터를 거치면 소리의 길이가 바뀌므로, 링 버퍼에 넣는 덩어리마다 원래의 미디어 시각을 함께 기록해 둡니다.

## 영상 경로

### 디바이스 공유

D3D11 디바이스를 하나만 만들어 디코더와 렌더러가 함께 씁니다. 이것이 "프레임은 GPU를 떠나지 않는다"의 전제입니다.

1. `D3D11_CREATE_DEVICE_VIDEO_SUPPORT`와 `D3D11_CREATE_DEVICE_BGRA_SUPPORT`로 디바이스를 만듭니다. 뒤의 것은 Direct2D 때문에 필요합니다.
2. `av_hwdevice_ctx_alloc`으로 FFmpeg 하드웨어 컨텍스트를 만들고, `AVD3D11VADeviceContext.device`에 이 디바이스를 넣은 뒤 `av_hwdevice_ctx_init`을 부릅니다.
3. 코덱 컨텍스트에 `hw_device_ctx`를 주고, `get_format`에서 `AV_PIX_FMT_D3D11`을 고릅니다.
4. 프레임 큐에 잡아 두는 장수만큼 `extra_hw_frames`를 늘립니다. 디코더의 텍스처 풀은 크기가 고정이라, 이 값이 모자라면 디코딩이 멈춥니다.

디코딩된 프레임은 `data[0]`에 `ID3D11Texture2D`, `data[1]`에 텍스처 배열의 인덱스를 담고 있습니다. 포맷은 8bit면 NV12, 10bit면 P010입니다.

> **주의.** FFmpeg와 렌더 스레드가 같은 디바이스 컨텍스트를 쓰므로 `AVD3D11VADeviceContext`의 `lock` / `unlock`으로 양쪽을 직렬화해야 합니다.

### 색 변환과 출력

NV12/P010을 화면용 RGB로 바꾸는 일은 D3D11 VideoProcessor에 맡깁니다. 색 변환, 크기 조절, 회전을 한 번의 `VideoProcessorBlt`로 스왑체인 백버퍼에 바로 씁니다.

- 스왑체인은 플립 모델(`DXGI_SWAP_EFFECT_FLIP_DISCARD`), BGRA 8bit입니다.
- 입력과 출력의 색공간(BT.601, BT.709, BT.2020, PQ, HLG)을 프레임 정보대로 지정합니다.
- 화면 비율과 회전 메타데이터는 출력 사각형과 회전 설정으로 처리합니다.

> **M1에서 가장 먼저 확인할 것.** 디코더가 만든 텍스처를 VideoProcessor 입력으로 그대로 쓸 수 있는지입니다. 드라이버가 거부하면 해당 슬라이스를 별도 텍스처로 GPU 안에서 복사한 뒤 입력으로 씁니다. 이 경우에도 시스템 메모리는 거치지 않습니다.

### 컨트롤 그리기

같은 백버퍼 위에 Direct2D로 컨트롤 바와 OSD를 그린 뒤 `Present`합니다. 글자는 DirectWrite, 아이콘은 도형으로 직접 그려서 이미지 파일을 싣지 않습니다.

일시정지 중에는 렌더 루프를 멈추고, 화면이 바뀌어야 할 때만 다시 그립니다.

### 소프트웨어 폴백

하드웨어 디코딩을 쓸 수 없으면 CPU로 디코딩한 프레임을 NV12/P010 텍스처에 올리고, 이후는 같은 경로를 탑니다. 렌더러는 프레임이 어디서 왔는지 모릅니다.

폴백으로 넘어가는 경우는 다음과 같습니다.

- GPU가 그 코덱이나 프로파일을 지원하지 않을 때 (예: HEVC 4:2:2)
- 디코더 초기화나 디코딩 중 하드웨어 오류가 났을 때
- 디바이스를 잃었을 때 (드라이버 재시작 등)

## 소리 경로

```
디코딩 → atempo (배속) → 포맷 변환 (장치의 샘플레이트, 채널, f32) → 링 버퍼 → 콜백 (음량 적용)
```

- 배속은 libavfilter의 `atempo`로 음정을 유지한 채 바꿉니다. 2배를 넘으면 2배 이하의 단계 여러 개를 이어 붙입니다.
- 배속을 바꿀 때는 필터 그래프를 다시 만들지 않고 `tempo` 명령을 보냅니다.
- 음량은 콜백에서 샘플에 곱합니다. 시스템 음량은 건드리지 않습니다.
- 출력 장치가 바뀌거나 사라지면 새 기본 장치로 다시 엽니다. 실패하면 벽시계로 넘어가 영상만 재생합니다.

## 탐색

1. UI 스레드가 목표 시각과 함께 세대를 올립니다.
2. 디먹스 스레드가 패킷 큐를 비우고, 목표 앞의 키프레임으로 파일 위치를 옮깁니다.
3. 디코더는 새 세대를 보면 내부 버퍼를 비웁니다.
4. 링 버퍼를 비우고 시계를 목표 시각으로 맞춥니다.
5. 모드에 따라 첫 프레임을 정합니다.
   - **빠른 탐색**: 키프레임을 바로 보여 줍니다. 탐색 바를 끄는 동안 씁니다.
   - **정확한 탐색**: 목표 시각 전의 프레임은 디코딩만 하고 버립니다. 키 입력과 탐색 바를 놓았을 때 씁니다.

탐색 요청이 처리 중에 또 들어오면 중간 것은 버리고 마지막 목표만 처리합니다. `→`를 누르고 있어도 밀리지 않게 하기 위해서입니다.

## 상태

```
비어 있음 ──열기──▶ 여는 중 ──▶ 재생 ◀──▶ 일시정지
    ▲                 │          │           │
    └────오류─────────┘          └──▶ 끝 ◀───┘
```

탐색은 별도 상태가 아니라 재생이나 일시정지 위에 얹히는 일시적 동작입니다. 일시정지 중에 탐색하면 새 프레임 한 장만 보여 주고 다시 멈춥니다.

## 모듈 구조

crate는 하나입니다. 워크스페이스로 나누지 않습니다.

```
src/
  main.rs          진입점, 명령줄 인자, 메시지 루프
  player.rs        상태 기계와 명령 처리
  clock.rs         소리 시계, 벽시계, 배속
  queue.rs         세대 번호가 붙은 유한 큐
  media/
    demux.rs       파일 열기, 패킷 읽기, 탐색
    video.rs       영상 디코딩 (D3D11VA, 소프트웨어 폴백)
    audio.rs       소리 디코딩, atempo 필터 그래프
    ffi.rs         안전 래퍼에 없는 FFmpeg 원시 API
  gfx/
    device.rs      D3D11 디바이스, 스왑체인
    present.rs     VideoProcessor 변환, 프레임 선택과 표시
    overlay.rs     Direct2D 컨트롤 바와 OSD
  audio_out.rs     출력 장치, 링 버퍼, 음량
  ui/
    window.rs      Win32 창, 전체화면, DPI, 끌어다 놓기
    input.rs       키와 마우스를 명령으로
    layout.rs      컨트롤 바 배치와 클릭 위치 판정
```

**순수 로직과 플랫폼 코드를 섞지 않습니다.** `clock`, `queue`, `ui/layout`, 탐색 병합, 배속 단계 계산은 Windows API를 부르지 않게 만들어, 어느 OS에서나 `cargo test`로 검증합니다. 개발 장비가 macOS이므로 이 구분이 곧 테스트할 수 있는 범위를 정합니다.

## Concat에서 참고할 것

Concat(`concat-media`)에 비슷한 문제를 푼 코드가 있습니다. Concat은 AGPL이므로 코드를 복사하지 않고 접근 방식만 참고합니다.

| 파일 | 참고할 점 | 다른 점 |
|---|---|---|
| `hardware.rs` | 하드웨어 디코더 선택과 실패 시 폴백 처리 | Concat은 프레임을 시스템 메모리로 복사합니다. GongPlayer는 GPU에 둡니다 |
| `audio.rs` | `atempo` 단계 나누기, 프레임 사이에 남는 샘플 처리 | Concat은 내보내기용 필터 그래프입니다. GongPlayer는 재생 중에 배속을 바꿉니다 |
| `decode.rs` | 회전 메타데이터, 타임스탬프 처리 | Concat은 임의 위치 프레임 추출이 중심입니다. GongPlayer는 순차 재생입니다 |
