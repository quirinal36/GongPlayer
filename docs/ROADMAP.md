# 로드맵

MVP까지 일곱 단계입니다. 위험한 것을 먼저 확인하는 순서로 짰습니다. 기간은 혼자 전업으로 작업할 때의 어림값이고, 합계는 3~4주입니다.

각 단계는 "완료 기준"을 실제 Windows PC에서 확인해야 끝난 것입니다. 작업을 마치면 체크박스를 채웁니다.

| 단계 | 내용 | 기간 |
|---|---|---|
| M0 | 기반과 위험 확인 | 1~2일 |
| M1 | 영상 출력 | 3~4일 |
| M2 | 소리와 동기화 | 3~4일 |
| M3 | 일시정지, 탐색, 배속 | 3~4일 |
| M4 | 컨트롤과 조작 | 3일 |
| M5 | 견고성 | 4~5일 |
| M6 | 경량화와 배포 | 2~3일 |

## M0. 기반과 위험 확인

코드를 본격적으로 쓰기 전에, 계획을 뒤집을 수 있는 것부터 확인합니다.

- [ ] `git init`, Cargo 프로젝트, 릴리스 프로필
- [ ] CI: Windows 러너에서 `fmt`, `clippy`, 빌드, 테스트
- [ ] 개발용 FFmpeg 고정: 사전 빌드 `win64-lgpl-shared`를 URL과 sha256으로 고정
- [ ] 개발 흐름 결정: Windows PC에서 직접 개발할지, macOS에서 편집하고 Windows에서 실행할지 ([BUILD](BUILD.md))
- [ ] 스파이크 A: 빈 Win32 창에 D3D11 스왑체인으로 단색 화면 표시
- [ ] 스파이크 B: 최소 구성 FFmpeg 정적 라이브러리가 Rust 실행 파일에 링크되는지 확인
- [ ] 테스트 영상 세트 수집 ([BUILD](BUILD.md)의 목록)
- [ ] 기준 PC 사양을 [BUILD](BUILD.md)에 기록

**완료 기준**

- Windows PC에서 `cargo run`이 창을 띄웁니다.
- CI가 통과합니다.
- 스파이크 B의 결론이 [DECISIONS](DECISIONS.md)에 적혀 있습니다. 실패하면 배포 형태를 "exe와 최소 DLL"로 바꿉니다.

## M1. 영상 출력

가장 위험한 부분입니다. 디코더 텍스처가 복사 없이 화면까지 가는지 확인합니다.

- [ ] 명령줄 인자로 받은 파일 열기, 영상 스트림 고르기
- [ ] 디먹스 스레드와 패킷 큐
- [ ] D3D11 디바이스를 FFmpeg와 공유, D3D11VA 디코딩
- [ ] VideoProcessor로 NV12/P010을 백버퍼에 변환
- [ ] 렌더 스레드: 벽시계 기준으로 프레임 표시
- [ ] 창 크기 변경 시 비율 유지

**완료 기준**

- 1080p H.264와 4K HEVC 10bit 파일이 제 속도로 끝까지 재생됩니다.
- 작업 관리자에서 GPU의 Video Decode 사용이 보이고, CPU 사용은 한 자릿수 %입니다.
- 창을 끌거나 크기를 바꾸는 동안에도 재생이 끊기지 않습니다.

## M2. 소리와 동기화

- [ ] 소리 디코드 스레드, 장치 포맷으로 변환, 다운믹스
- [ ] 출력 장치 열기, 링 버퍼, 콜백
- [ ] 소리 시계 구현, 렌더 스레드의 기준을 벽시계에서 소리 시계로 교체
- [ ] 소리 없는 파일은 벽시계로 재생
- [ ] `clock`, `queue` 단위 테스트

**완료 기준**

- 립싱크 테스트 영상에서 10분 재생 뒤 영상과 소리의 어긋남이 ±40ms 이내입니다.
- 소리 없는 영상과 5.1 채널 영상이 정상 재생됩니다.

## M3. 일시정지, 탐색, 배속

- [ ] 상태 기계 (`player.rs`)
- [ ] 일시정지: 시계 정지, 소리 출력 정지, 렌더 루프 휴면
- [ ] 세대 번호를 이용한 탐색, 빠른 탐색과 정확한 탐색
- [ ] 연속 탐색 병합
- [ ] `atempo` 배속, 재생 중 변경
- [ ] 파일 끝 처리
- [ ] 키보드로 임시 조작 (아직 컨트롤 바 없음)

**완료 기준**

- `→`를 누르고 있어도 화면이 밀리지 않고 따라옵니다.
- 빠른 탐색에서 키 입력 뒤 100ms 안에 새 프레임이 나옵니다.
- 0.5~4배 모든 단계에서 음정이 유지되고 동기가 맞습니다.
- 일시정지 중 CPU 사용이 0%입니다.

## M4. 컨트롤과 조작

- [ ] Direct2D 오버레이: 컨트롤 바, 탐색 바, OSD
- [ ] 배치와 클릭 위치 판정 (`ui/layout.rs`, 단위 테스트 포함)
- [ ] [SPEC](SPEC.md)의 모든 단축키와 마우스 조작
- [ ] 전체화면, 자동 숨김, 커서 숨김
- [ ] 끌어다 놓기, 파일 열기 대화상자
- [ ] 모니터별 DPI 대응
- [ ] 빈 상태와 오류 표시

**완료 기준**

- [SPEC](SPEC.md)의 조작 표에 있는 모든 항목이 동작합니다.
- 배율이 다른 모니터 사이로 창을 옮겨도 컨트롤 크기가 맞습니다.

## M5. 견고성

실제 파일과 실제 환경에서 깨지는 곳을 메웁니다.

- [ ] 소프트웨어 디코딩 폴백, 재생 중 전환 포함
- [ ] 회전 메타데이터, 화소 비율
- [ ] 가변 프레임레이트
- [ ] HDR(PQ, HLG) 영상을 SDR로 변환
- [ ] 손상되거나 중간에 잘린 파일
- [ ] 소리 장치 변경과 분리
- [ ] 디바이스 손실, 모니터 변경, 절전 복귀
- [ ] 재생 중 화면 꺼짐 방지
- [ ] 큐 크기 실측과 조정

**완료 기준**

- 테스트 영상 세트 전부가 재생됩니다.
- 재생 중에 헤드폰을 뽑거나 창을 다른 모니터로 옮겨도 재생이 이어집니다.
- 아이폰 HDR 영상의 색이 바래 보이지 않습니다.

## M6. 경량화와 배포

- [ ] 최소 구성 FFmpeg 빌드 스크립트, 정적 링크 (M0 스파이크 B의 결론에 따름)
- [ ] 크기, 시작 시간, 메모리, CPU 실측
- [ ] 실측값으로 [PHILOSOPHY](PHILOSOPHY.md)의 예산 표 갱신
- [ ] CI에 실행 파일 크기 검사 추가
- [ ] 아이콘, 버전 정보, 매니페스트
- [ ] 파일 연결 등록 방법 결정
- [ ] `THIRD_PARTY_NOTICES`, 프로젝트 라이선스 결정

**완료 기준**

- 예산 표의 모든 항목을 충족하거나, 조정한 이유가 [DECISIONS](DECISIONS.md)에 적혀 있습니다.
- 깨끗한 Windows에 exe 하나만 복사해 HEVC 파일을 재생할 수 있습니다.

## 위험 요소

| 위험 | 영향 | 대응 |
|---|---|---|
| 개발 장비가 macOS | 하드웨어 디코딩과 화면 출력을 개발 장비에서 확인할 수 없음 | 실제 Windows PC에서 검증. Apple Silicon의 가상 머신은 GPU 디코더가 없어 대체 불가 |
| CI 러너에 GPU가 없음 | 자동 테스트가 소프트웨어 경로만 확인 | 순수 로직을 분리해 단위 테스트. 하드웨어 경로는 단계마다 수동 확인 |
| 디코더 텍스처를 VideoProcessor가 거부 | 복사 없는 경로가 일부 드라이버에서 실패 | M1에서 가장 먼저 확인. GPU 안에서 복사하는 우회로 준비 |
| 정적 링크의 툴체인 조합 | 단일 exe 목표가 흔들림 | M0 스파이크 B. 실패하면 exe와 최소 DLL로 배포 |
| HDR 변환 품질이 드라이버마다 다름 | 일부 PC에서 색이 다르게 보임 | M5에서 GPU 제조사별 확인. 부족하면 셰이더로 직접 톤매핑 |
| GPU 제조사별 동작 차이 | 한 PC에서만 되는 코드 | 가능한 범위에서 Intel, NVIDIA, AMD 각각 확인 |
| 범위가 불어남 | 가벼움과 일정이 함께 무너짐 | [PHILOSOPHY](PHILOSOPHY.md)의 세 질문, [SPEC](SPEC.md)의 "하지 않는 것" |
